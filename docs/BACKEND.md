# Using `aic` as a module for a backend

`aic` is a **library** with two equivalent entry points, CLI and HTTP. Both call into the same
façade, [`aic.service.Engine`](../src/aic/service.py); no logic exists on only one path.

```
                    ┌─────────────────────┐
   aic <command> ──► │                     │
                    │  aic.service.Engine │ ──► core / index / query / tasks / submit
   POST /solve   ──► │                     │
                    └─────────────────────┘
   aic/cli.py          aic/api/app.py
   (presentation)      (transport)
```

---

## 1. Running it in three lines

```bash
uv sync --extra backend
uv run aic serve --port 8000       # or: uv run uvicorn aic.api.app:app --port 8000
# open http://127.0.0.1:8000/docs
```

Without a real encoder, add `--allow-stub` so the pipeline runs; `/health` then reports
`status: "degraded"` and every response carries `degraded: true`.

### What one engine holds

`Engine.load()` loads five things, and two of them are optional in a way a caller should know about:

| Field | Contents | If absent |
|---|---|---|
| `dense` | 173 MiB of keyframe vectors, `float16`, memory-mapped | fatal — nothing can run |
| `shots` | shot table (176,707 shots) | fatal |
| `text` | BM25 over `media-info` | the sparse and entity channels fall silent |
| `title` | BM25 over titles only | the highest-weighted sparse channel falls silent |
| `encoder` | `clip-ViT-B-32` text tower, 512 dimensions | fatal unless `allow_stub=True` |
| `encoder_multilingual` | a second tower in the same image space, reading Vietnamese directly | a **warning** in `/health`; the English tower carries the query alone, which it does poorly for Vietnamese prose |

An optional piece missing never raises: it appends to `Engine.warnings`, which `/health` returns.
That is deliberate — a backend answering 200 OK while one retrieval channel is silent is exactly the
failure that should be visible without reading logs.

## 2. Embedding it directly, without HTTP

```python
from aic.service import Engine

engine = Engine.load()  # load ONCE at startup
result = engine.solve("một diễn giả mặc áo đỏ", query_id="7")

# Q&A answers come from the caller until a VQA model exists (CONSTRAINTS G5): the answer axis is
# one of three conjuncts, so a row without it cannot score. `pins` puts rows a human has verified
# by looking at the frame at the head of the list, where slot 1 is worth a fifth of the score.
result = engine.solve(
    text,
    query_id="p1-15",
    answers=[("Giang Ly", 0.5), ("Xã Giang Ly", 0.35)],
    pins=[("L30_V072", 676)],
)

result.n_answers  # 100
result.expected_final  # E[Final Score]
result.to_dict(top=5)  # plain JSON dict, ready for a response body
result.rows()  # the rows exactly as they appear in the submission file
engine.write(result)  # write the CSV, with validation
```

`Engine.load()` reads `configs/default.json` from the project root and makes every path absolute.
It does not depend on the process working directory — see §5.

## 3. The endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Engine state: `ready` / `degraded` / `loading` / `error`, plus `warnings` |
| `POST` | `/solve` | Solve one query, returning up to 100 ordered answers |
| `POST` | `/solve/batch` | Solve a batch (at most 50). One failing query does not fail the batch |
| `POST` | `/parse` | Parse the query only — fast, no retrieval |
| `GET` | `/videos/{video_id}` | fps, keyframe count, duration, so a client can map frames to seconds |
| `GET` | `/docs` | OpenAPI, generated by FastAPI |

A response, abbreviated to its decisive fields:

```json
{
  "degraded": true,
  "n_answers": 100,
  "allocation": {"expected_final": 0.136123},
  "answers": [
    {"rank": 1, "video_id": "L30_V033", "frame_id": 540,
     "gain": 0.014444, "cumulative": 0.014444, "source": "shot#9@step25"}
  ]
}
```

**`rank` is part of the contract.** Answer order *is* the score — `R@k` takes the maximum over the
first `k` rows. A client must not reorder this list.

**`degraded` is at the top level of the response**, not buried in `notes`. It is true when the
result is **not** usable for a submission: the encoder is a stub, or Q&A has no VQA model, or TRAKE
is running in keyframe-only mode. A client should treat `degraded: true` as "not usable yet".

## 4. Three operational decisions

### 4.1. The engine is a singleton, loaded once

Loading takes seconds to tens of seconds: a 173 MiB dense index, a 176,707-row shot table, the text
index, plus the encoder. `get_engine()` wraps loading in a `threading.Lock`, so several requests
arriving together at startup do **not** load several copies and exhaust RAM.

Set `AIC_EAGER_LOAD=1` (the default for `aic serve`) to load during startup: "index missing" becomes
an immediately visible startup error rather than a 500 on the first user request. Loading runs in a
threadpool so the event loop is never blocked, and if it fails the process stays alive so `/health`
can report why.

### 4.2. Concurrency is bounded

`Engine.solve` is CPU-bound: a 177,321 x 512 matrix multiplication plus greedy over 500 candidates,
about **0.7 s** per query on the development machine. Running unlimited requests in parallel does
not make it faster — it makes every request uniformly slower and risks exhausting RAM. Bound it with
`AIC_MAX_CONCURRENCY` (default 2) or `aic serve --concurrency N`.

For higher throughput, run several worker **processes**; but each worker holds its own copy of the
index (~600 MB RSS), so multiplying workers multiplies RAM.

### 4.3. The library logs, it does not print

`aic` never prints to stdout. Signals go through the `aic` logger ([`aic.log`](../src/aic/log.py));
the CLI attaches a handler writing to **stderr**, and a backend attaches its own:

```python
import logging

logging.getLogger("aic").addHandler(my_handler)
```

Warnings raised while loading are **collected** into `Engine.warnings` and returned by `/health`,
rather than vanishing into a log. One deliberate exception: the index-building functions take a
`verbose` flag and log progress directly — those are hand-run operations lasting tens of minutes,
and the caller asked for it explicitly.

## 5. Paths: relative to the project root, not the CWD

A server process has an arbitrary working directory. `configs/default.json` therefore holds
**relative** paths, and `load_config()` joins them to the *project root* found by
`aic.config.find_project_root()`, which walks up from `aic/config.py` to `pyproject.toml`.

| Environment variable | Purpose |
|---|---|
| `AIC_PROJECT_ROOT` | Override the project root, for deployments where code and data sit apart |
| `AIC_DATA_ROOT` | Override the corpus location; beats the config file |
| `AIC_EAGER_LOAD` | `1` = load the engine at startup |
| `AIC_MAX_CONCURRENCY` | How many `solve` calls run in parallel (default 2) |
| `AIC_ALLOW_STUB` | `1` = permit the stub encoder; `/health` reports `degraded` |

`data/batch1` is a **directory junction** pointing at the real corpus (107 GiB), created by
`python scripts/link_data.py`. Thanks to it the configured path is `data/batch1` on every machine, and
the link is the only place that knows where the data actually is.

Generated output goes to `data/processed/` (index, reports, submissions, video cache) — all of it
reproducible, all of it git-ignored.

## 6. The core package depends on no web framework

`fastapi` arrives only with `uv sync --extra backend`, and it is imported only when somebody
actually **touches** `aic.api.create_app` (`aic/api/__init__.py` uses `__getattr__` for lazy
import). That is what lets `aic validate`, `aic build-index` and the whole test suite run in an
environment with no web package at all. The property is locked by a test:
`tests/test_api.py::test_importing_aic_does_not_pull_in_fastapi` runs a subprocess and asserts
`fastapi` is absent from `sys.modules`.

The request and response contract ([`aic/api/schemas.py`](../src/aic/api/schemas.py)) is written
with standard-library dataclasses, **not** pydantic: the validation rules must apply to HTTP callers
and in-process callers alike, so they live in `SolveRequest.validated()` rather than in a framework
decorator.

Boundary validation also covers things that are not about data shape. `query_id` becomes part of a
**submission filename**, so path characters are rejected at `validated()` before they can escape a
directory.

## 7. What is missing before this goes anywhere real

`/health` reports `degraded` until a real encoder is present (`uv sync --extra encoder`, see
[CONSTRAINTS.md](CONSTRAINTS.md) item C4). Beyond that, what a real backend needs and this layer
does **not** have, in order:

1. **Caller authentication.** There is none. The assumption is a reverse proxy on an internal
   network.
2. **Rate limiting.** The semaphore protects against overload, but there is no per-client limit.
3. **A per-query cache.** The same query is recomputed from scratch every time. The query text is a
   natural cache key and results are deterministic (fixed `seed`), so this is cheap to add.
4. **Serving keyframes.** A client wants to *see* the frames returned. The keyframes are extracted
   and `DirSet.local_path()` returns a real path, so an image endpoint is small work — but path
   traversal has to be thought through before opening anything.
